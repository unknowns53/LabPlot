# ポータルの使い方

LabPlot の配布物に同梱されている `LabPlot.Avalonia(.exe)` は、3 つの解析モジュール（GPC / Spectrum / DLS）を 1 本にまとめたポータル（ランチャー）です。各モジュールはクラスライブラリとしてポータルに組み込まれているので、配布物の中に「単独で起動できる exe」は他にありません。

> 対象: LabPlot v1.2.0（Avalonia 主流版）

---

## ポータルとは

ポータルの役目は次の 4 つです。

1. カード型のランチャー画面を表示し、利用者が解析モジュールを選べるようにする
2. 選ばれたモジュールの解析ウィンドウを開く
3. 同じモジュールが二重に起動しないようにする
4. 例外が発生したらログに書き出す

これらは `LabPlot.Avalonia(.exe)` 1 本がすべて担当します。

---

## カード型ランチャーの操作

ダブルクリックで起動すると、540 × 620 のウィンドウが現れます。中央に 2 × 2 のカードグリッドが表示され、左上から順に「GPC」「UV-Vis」「DLS」のカードが並びます（4 つ目は今後の解析モジュール用の空セルです）。

カードをクリックするとそのモジュールの解析ウィンドウが立ち上がり、ポータル自体は背景に残ります。

> （スクリーンショット予定: docs/user-guide/images/portal/00-launcher.png）

---

## ウィンドウまわりの操作

ポータルおよび各モジュールのウィンドウは、Windows 標準のタイトルバーを外して、自前のチタイルバー（`CustomTitleBar`）に置き換えています。これにより、Windows / macOS / Linux で見た目が共通になっています。

- 上部のバーをドラッグするとウィンドウを移動できます。
- 右上の最小化 / 最大化（復元）/ 閉じるボタンは標準の挙動と同じです。
- ダブルクリックで最大化と通常サイズの切替ができます。

> （スクリーンショット予定: docs/user-guide/images/portal/10-titlebar.png）

---

## 重複起動の挙動

GPC のウィンドウを開いたあと、ポータルに戻ってもう一度「GPC」カードをクリックしても、新しいウィンドウは開きません。代わりに、すでに開いている GPC ウィンドウが手前に来ます。これは作業中のモジュールが意図せず複数立ち上がってしまうのを防ぐためです。

UV-Vis や DLS も同じ挙動です。複数のモジュールを同時に開く（例: GPC と Spectrum を 1 つずつ）のは可能で、それぞれが独立したウィンドウとして並びます。

---

## ポータル終了時の挙動

ポータル本体（カード型ランチャー）を × で閉じると、開いている GPC / Spectrum / DLS のウィンドウもまとめて閉じます。これは「ポータル＝親プロセス」というシンプルなライフサイクルにしてあるためです。

各モジュールのウィンドウだけを閉じてポータルに戻る場合は、そのモジュールのウィンドウを × で閉じれば OK です。ポータルは生き残っているので、ランチャーから別のモジュールを開けます。

---

## ログの場所

予期しない例外が起きた場合、ポータルが OS のユーザー領域にログを書き出します。

| OS | ログパス |
| --- | --- |
| Windows | `%LocalAppData%\LabPlot\Logs\shell-error.log` |
| macOS | `~/Library/Application Support/LabPlot/Logs/shell-error.log` |
| Linux | `~/.local/share/LabPlot/Logs/shell-error.log` |

ログには例外の発生時刻、種類、メッセージ、スタックトレースが追記されていきます。アプリが急に落ちたり、何度試しても同じ操作で異常終了する場合は、このファイルを確認すると何が起きたかの手がかりが得られます。

ログ書き出しは UI スレッド・タスクスケジューラ・AppDomain の 3 経路を購読しているので、画面に出ないバックグラウンドの例外も拾われます。

---

## ログを開発元に送る場合

研究室の管理者やリポジトリ運営者に問題を報告するときは、`shell-error.log` の中身に加えて、次の情報を添えると再現が早くなります。

- 発生した日時
- 操作の流れ（どのモジュールで、どのファイルを開いて、どのボタンを押したか）
- 期待した挙動と、実際の挙動の差
- OS とそのバージョン（Windows 11 / macOS 14.2 など）
- LabPlot のバージョン（GitHub Releases から取得した zip の名前で OK）

GitHub の Issues に投稿する場合のテンプレートは [トラブルシューティング](./troubleshooting.md) の最後のセクションにまとめてあります。
